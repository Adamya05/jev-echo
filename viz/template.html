What this does and doesn't show

Cost is the weakest reason to do this

Jev is $0.042 per million input tokens. A whole game costs about a quarter of a cent. Nobody should move a workload on-device to save that.

The reasons that hold up: the board never leaves the machine — trivial for a game, decisive for the accessibility-tree computer-use loop elsewhere in this project, where the prompt is whatever is on your screen. You can retrain it on your own distribution in 27 seconds; you cannot retrain Jev at all. 87 KB runs anywhere — no network, no key, no rate limit, no dependency on a company continuing to serve a model. It is deterministic: same input, same output, forever, with no silent version bumps. Speed is just the measurable proxy.

  • Identical input on both sides. Jev gets the 10×10 ASCII grid as text; the student gets the same grid as three planes. No flood fill, no distances, no derived facts for either.
  • The student never saw these boards. Trained on seeds 3000–3089; every seed here is 0–9.
  • The time budget is enforced against the clock, not a rollout count, so the equal-budget comparison stays honest on different hardware.
  • Laya is the missing control. 322M parameters, same local hardware, same raw board — and it scored 0.7. Being local is not what makes this work; distilling a good teacher is.
  • One task. 10×10 grid, four moves. Jev answers arbitrary typed questions about arbitrary state; the student does Snake.
